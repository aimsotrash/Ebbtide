# Dory.md backend — PINNED production dependencies.
#
# Why pinned: reproducible builds + a fixed surface for `pip-audit` (P0 dependency
# security). Unpinned ranges let a transitive bump silently change what ships.
#
# Verification status:
#   - The web/auth/data subset (fastapi, uvicorn, chromadb, python-jose, bcrypt,
#     numpy, python-docx, python-multipart, python-dotenv, fsrs) is the same set
#     verified by the test suite (see requirements-test.txt) and is exercised in
#     CI on Python 3.12.
#   - The heavy ML stack (torch, sentence-transformers, scikit-learn, pdfplumber,
#     beautifulsoup4) and the LLM SDKs (groq/openai/anthropic) are pinned to
#     known-compatible releases for the torch 2.5.1 + Python 3.12 deploy target
#     (the Dockerfile uses python:3.12-slim). torch has no cp314 wheel, so the
#     full install is validated on 3.12 in the build pipeline, not on 3.14.
#   - See docs/DEPENDENCY_UPGRADES.md for the upgrade/lock workflow.
